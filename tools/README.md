# tools/

Scripts that run on your computer (Node 18+), never in the extension or the Worker.

## prefill.mjs — static hint files for every problem

Generates hints once per problem and writes `cache/<slug>.json` + `index.json` for the
`leethint-cache` Pages site, so most users never trigger an AI call.

```bash
cd backend && npx wrangler dev        # local Worker, with a DEVELOPMENT key in backend/.dev.vars
node tools/prefill.mjs --out ../leethint-cache --limit 20     # in another terminal
```

| Option | Default | |
|---|---|---|
| `--server <url>` | `http://localhost:8787` | Worker to use (the live one uses the users' quota — avoid) |
| `--out <dir>` | `prefill-out` | Folder that gets `cache/` and `index.json` (point it at the `leethint-cache` checkout) |
| `--limit <n>` | all | Stop after n new files |
| `--only <slug>` · `--force` | | One problem / regenerate even if current |
| `--delay <s>` | 20 | Pause between problems |

Every file is checked before it's saved: 4 hints, TC/SC, code, LeetCode's exact
signature, and the C++ **compiles** (clang++ or g++ on this computer; LeetCode's helper
types like `ListNode` come from the starter code). A compile error is sent back to the
AI once; problems that still fail are listed in `<out>/needs-review.txt`. Runs are
resumable (files with the current `PROMPT_VERSION` are skipped) and stop after 3 "all
providers busy" replies in a row. Popular (company-tagged) problems go first.

Weekly, the `sync-cache` GitHub Action runs it against the live Worker for the
week's new problems (already generated by the Worker's Monday cron).

## accuracy/ — measure before shipping a prompt or routing change

```bash
node tools/accuracy/standard.mjs          # 10 standard problems: examples + edge cases, Python run, Hint 1 spoilers
python3 tools/accuracy/hard/gen.py        # once: brute-force test drivers for 5 very hard problems
node tools/accuracy/hard/run.mjs          # 5 very hard problems: 300 random tests each + max-size timing
```

Both use `BACKEND=<url>` (default `http://localhost:8787`). Pass marks as of prompt `p6`
(5 Nov 2026): 10/10 standard, at least 4/5 very hard. A prompt change bumps
`PROMPT_VERSION`, so the run misses the cache and tests the new prompt. Run against a
Worker with **Groq** (a dev key in `backend/.dev.vars`): Workers AI alone through
`wrangler dev` cuts streams off and isn't a fair test.

## leetcode.mjs
